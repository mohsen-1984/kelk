## 3. Decisions

1. **What a golden holds:** the HTML export, the `.docx`'s XML (all parts but `docProps/`, whose dates and
   application change every run), the `.doc`'s parts, the PDF read back as Markdown, and the `.docx` read back as
   Markdown — not PDF bytes or glyph positions (fonts and timestamps), not pictures' bytes.
2. **Raster pictures are never kept**, only their type: a formula's PNG fallback is drawn on a canvas, whose
   anti-aliasing differs between platforms. SVG, fonts and other vector data are kept as size + SHA-256, long SVG
   path outlines (MathJax glyphs, hundreds of KB per formula document) as length + hash: a change still fails.
3. **Shared sections** (`expected/_shared/`): the `.docx` boilerplate and the CSS heads repeat in every case; stored
   once they bring the snapshots from 10.3 MB to 2.7 MB. A change of one shows as a diff of the expanded text.
4. **Fonts in the golden page:** `MathCore.exRatio` sizes a formula by the document font's x-height, measured in
   the page. The suite page has no `@font-face`, so it measured the system's serif fallback (Times New Roman on
   Windows: 0.447; another font on Linux) — formula sizes would differ by machine. `build.js` adds the bundled web
   fonts as faces first (Vazirmatn now measures 0.528, as in the app). Only the two formula cases' snapshots depend
   on it. The builder suite page itself is unchanged.
5. **The about/guide documents are not in the goldens:** they are the app's content and change with every wording
   edit; they stay in the builder suite and in `docx-validate.js`.
6. **Schemas committed, not downloaded:** 0.68 MB, unchanged files with their SHA-256 and licence, so CI needs no
   network and a moved ECMA URL cannot break it. Transitional, not Strict: docx.js writes Transitional.
7. **Markup Compatibility before validation**, as Word reads the file: docx.js declares `w14 w15 wp14` ignorable;
   validating them against the 2016 schemas would report Office extensions, not errors. With that, the allow-list is
   **empty** — every docx.js part validates as it is.
8. **`docProps/core.xml` is not schema-checked** (its schema imports Dublin Core from dublincore.org); it is
   checked for well-formedness.
9. **Two `lib/` fixes, both small and proven by a failing check:** `MathCore` (schema), `MarkdownImporter` (unit
   tests). A rule in a table cell becomes a line break — a GFM cell cannot hold a rule; a rule inside running text is
   dropped — Markdown has no inline rule; a rule list item goes into the item before it, so the list is not split.
10. **apt versions pinned to `noble-updates`** (current, with security fixes) rather than the immutable release
    pocket (LibreOffice 24.2.2 of 2024, whose exact-version dependencies would need every LibreOffice package pinned):
    the price is a bump when Ubuntu replaces a version (the step says so).
11. **One workflow of its own** (`builders.yml`), run on every change: `tooling.yml` has no browser or LibreOffice,
    `pdf-lab.yml` runs only on the lab's paths (it keeps its own `roundtrip.js` step).

## 6. Open issues

- **DOCX drops page breaks** (`page-breaks`): `PdfBuilder` breaks the page, the `.html` and `.doc` keep the CSS
  `page-break-before` / `break-after`, `DocxBuilder` writes neither `w:pageBreakBefore` nor `w:br w:type="page"`. The
  golden records today's output; a fix changes `page-breaks/docx.xml`.
- **Internal links through a `.docx` come back as bookmark names** (`links-internal/docx.md`):
  `[part two](#bm_part_two)` for `#part-two`; through a PDF they are lost (`pdf.md`: plain text; the external link
  is kept).
- **A ToC read back from the PDF** runs titles and page numbers together (`toc-ltr/pdf.md`: `contents1 Chapter 11`).
- **A pinned apt version disappears** when Ubuntu publishes an update (decision 10); the job then fails at install.
- xmllint's libxml2 differs between the local stand-in (2.11.9) and CI (2.9.14); first CI run to confirm.
- `THIRD-PARTY-NOTICES.md` lists shipped files only; the test schemas carry their notice in
