## 1. What changed

Every layout literal of the importer is a named entry of one registry, read through `this._t(name, ctx)`; the
document's own measures are computed once after extraction; the rules that change the output count themselves.
Defaults are the old literals, so the output is byte-identical — P3.3 switches entries to calibrated values.

| File | Change |
|---|---|
| `lib/pdfimport/thresholds.js` (new) | The registry `PdfImporter._thresholds`; each part defines its own entries with `PdfImporter._defineThresholds({ name: { def, unit, used, calib?, n?, minSamples?, on?, fixed? } })` (a name defined twice throws; entries frozen). `_t(name, ctx)`: the default, or — when an entry is `on` — `calib(cal, page)` if finite and `n ≥ minSamples`, else the default; `fixed` entries never calibrate. `_fire(rule, page)`, `_rulesStart`, `_rulesFinish` → `r.rules = { rule: { count, pages } }`; with `options.debug`, `r.calibration` (the measures and every threshold as resolved, with its source `def` / `cal` / `fixed`). |

The plan asked for ≥ 60 registered thresholds; the parts hold about 1,000 literals that a rule compares against,
and all of them are registered (array indices, structural 0 / 1 / 2, Unicode ranges, loop bounds left as code).

### Rules that never fire on the corpus

Of 377 rules, about 120 never fire on the 144 corpus files (extract 31, lines 7, regions 9, order 27, blocks 27,
plus names found only through a ternary). They are not bugs: most repairs were written for producers the
corpus does not hold (GSUB ligatures, small caps, colour emoji layers, dashed rules, OCR headings). The list is
the input for P4.1 / P4.2 — a real-producer file that makes a dead rule fire is a test the corpus lacks.

code token by token with the base (617 hunks exact, the other 194 read by hand: same pages, same operand order).
