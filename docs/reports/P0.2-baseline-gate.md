## 4. Acceptance

| Check | Result |
|---|---|
| `Object.keys(base.corpus).length === 144` | ✅ candidate: 144 (55 with `rtl`) |
| Disabling the ZWNJ rule locally fails the gate | ✅ exit 1: 21 files fail on right-to-left details, 19 on total (40 failures) against the candidate |
| A filtered run + `--update` is refused | ✅ exit 1: "this run holds 2 corpus files, the lab 144 — missing … (142)" |
| `--partial` merges; with no baseline it is refused | ✅ / ✅ |
| Clean run against the candidate | ✅ passed |

**The deliberate break.** ZWNJ (Persian half-space) is set by two rules that back each other up:
`lib/pdfimport/extract.js:813` (Chrome's zero-width space between Arabic letters → ZWNJ) and `lib/pdfimport/lines.js:489`
(a narrow or no-room space between Arabic letters → ZWNJ). Switching off either alone barely moves the gate — off
`extract.js` only, one file fails (`chrome-positioned--positioned` rtl 100 → 45.3); off `lines.js` only, nothing fails.
Both off (two-line diff kept at `C:/Users/Ali/kelk-lab-out/zwnj-sabotage.diff`, applied on a throwaway worktree only):
corpus mean 95.7 → 94.7, e.g. `lowriter--merged` rtl 100 → 62.7, `lohtml-rtl--fa-report` 71.8 → 45.2,
`kelkdocx-lo--fa-article` total 95.9 → 56.3. The committed baseline (2 files) would have caught none of it.

**Side finding:** with `lines.js:489` off, the three `wk-rtl--*` files score *better* (`zwnj` 0 → 10–24, `rtl` +3 to
+7.5): the narrow-space rule misreads wkhtmltopdf's Persian. Added to Known Issues for the P3.3 word-space batch.

## 5. Review

An independent review of the gate diff found two defects, both fixed and re-tested: `--partial` with no baseline file
wrote a 2-file baseline and so bypassed the guard; the new "rtl vanished" failure could only be triggered by a missing
corpus document, not by the importer (`score.js` gives `rtl` 0, not undefined, when the output loses it) — replaced by a
general "no longer scored" failure for any file. Also applied: the same `.pdf` stripping as `run-import.js`, `--k=v`
option form, exit 2 for the `--update --against` usage error.
