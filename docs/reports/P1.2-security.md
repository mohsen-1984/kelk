## 3. Behaviour notes

- **Ids of the document.** An `id` written in the Markdown's HTML is now `user-content-<id>` in the preview and in
  every export (the builders read the preview). Links of the document to its own ids are rewritten, so `[x](#part)`
  still jumps. A link from *outside* to `file.html#part` no longer finds the id.
- **Removed from the preview:** `<style>` blocks, `form`, `input`, `button`, `textarea`, `select`. The one
  exception is the **task-list checkbox**: marked 18 renders GFM `- [ ]` / `- [x]` as `<input type="checkbox"
  disabled>`, the builders turn it into ☐ / ☑, and the shipped samples use it — forbidding `input` removed the box
  (found while checking this sub-phase). The sanitiser leaves a mark where a checkbox stood and the preview puts
  back a disabled checkbox made by the app (`checked` kept, every other attribute dropped): the HTML is exactly
  marked's as before. A raw-HTML `<input type="checkbox">` becomes the same disabled box; any other input goes.
- **Inline `style` attributes stay** (documents colour text and cells with them); `'unsafe-inline'` in `style-src`
  is needed for them, for the builders' and MathJax's styles.
- **Header / footer.** The sanitiser keeps everything the shared header / footer model reads (tables, `p`, `div`,
  `b`, `i`, `u`, `span`, `a href`, `img`, `br`, inline `style`, `{page}` / `{pages}` / `{date}` / `{title}`).
- **Library use.** `HtmlBuilder` now cleans any HTML it is given, not only the app's sanitised preview. Form
  markup is kept by the builder (it is document content there); the app's sanitiser removes it first.

### Decisions

1. **`img-src` also allows `https:` and `http:`.** The plan lists `img-src 'self' data: blob:`, which blocks every
   remote image in the preview; the handbook (Security Architecture → Processing) states that a document may name
   a public image URL and the browser fetches it. An image cannot run script, so the widening costs only the
   request itself (privacy), which the app already accepted. Measured: the remote image is requested, no
   violation. To restore the plan's letter, drop `https: http:` — remote images then show broken in the preview.
2. **Added `object-src 'none'`, `base-uri 'self'`, `form-action 'none'`.** No plugin, `<base>` or form submission
   is used by the app; measured: no violation. No `default-src`: fonts (`FontFace` from the bundled data), `fetch`
   of remote images for the exports (ImageCore, `connect-src`) and blob downloads stay unrestricted, as the plan's
   list implies.
3. **One policy for `file://` and http.** The risk named in the plan — `'self'` not matching `file:` URLs — was
   measured in Chromium 141: on `file://`, `'self'` matches the app's own files (all start-up scripts and the
   libraries loaded on first use: docx, jsPDF, pdf.js, MathJax), with 0 violations. pdf.js already runs with
   `isEvalSupported: false` (`lib/PdfImporter.js:1102`), so no `unsafe-eval`. **One addition after the review:**
   `'wasm-unsafe-eval'` in `script-src` — pdf.js decodes JPEG 2000 and JBIG2 / CCITT images with WebAssembly on the
   page's own thread (`useWasm: true`, `vendor/pdfjs/wasm/`, no pure-JS fallback shipped), and `script-src 'self'`
   alone refuses to compile it, so scanned PDFs would lose their pictures (§4, finding 1). It allows compiling
   WebAssembly only, not `eval` of script.
4. **One sanitiser.** The header / footer goes through the preview's DOMPurify config (`K.preview.sanitize`), not
   a second list; it is applied after `{logo}` / `{author}` are filled, so the author link is checked too.
5. **Prefixed ids are kept in the exports** (not stripped back): the builders read the preview's HTML, and the
   exported document stays consistent with its rewritten internal links.
6. **`defang` goes beyond `on*` / `javascript:`** (embedded pages, `srcdoc`, `vbscript:`, script `data:` URLs):
   B4's point is that the HTML export never carries active content, whatever HTML the library gets.
7. **`rel="noopener noreferrer"` on every link with a `target`**, not only `_blank`: a raw-HTML `target="x"` opens a
   window too.
8. **Task-list checkboxes survive `FORBID_TAGS: ['input', …]`** through a DOMPurify `uponSanitizeElement` hook
   (added and removed around each call, so other DOMPurify users are untouched) and a rebuild by the app, rather
   than dropping `input` from the forbidden list: the plan's list stays as written, and no attribute of the
   document's own `<input>` reaches the page.
9. **The browser check is kept in the repository** (`tests/unit/csp-browser.js`) so it can be re-run after P1.4
   adds `scripts/boot.js` (a same-origin external script, which `script-src 'self'` allows); it is not in CI.

## 6. Open issues

- **Inline `style` can still overlay the preview**: `<div style="position:fixed;inset:0;z-index:9999">` stays inside
  the preview pane in Chromium (the pane is its containing block) but can fake content there, e.g. a "sign in" link
  (no script runs; the user can clear the text). Option: drop `position` / `z-index` in a DOMPurify hook for the
  preview pane only.
- **Other builders still parse into the live page**: `lib/BuilderBase.js:535` (`_mathToImages`),
  `lib/WordHtmlBuilder.js:610, 738, 743, 1276`, `lib/MathCore.js:511`. In the app their input is the sanitised
  preview; a library user passing raw HTML with `on*` handlers could still see them run there. Same fix as B4
  (`BidiCore.inertRoot`). Outside this sub-phase's files.
- **Measured in Chromium only.** Firefox and Safari were not run (only Chromium is installed by `npm ci`);
  Firefox's handling of `'self'` on `file://` is not measured.
- **Not settable by `<meta>`:** `frame-ancestors` (clickjacking), `report-uri`; GitHub Pages cannot send headers.
- **The exported HTML has no CSP of its own.** It carries no script (tested); a `<meta>` CSP `script-src 'none'` in
  the HTML export would make that explicit for whoever opens it.
- `tests/unit/csp-browser.js` is not in CI; `tooling.yml` would need Playwright's Chromium (`pdf-lab.yml` already
  installs it).
