## 3. Behaviour notes

- **Existing users.** A stored profile without `schemaVersion` is migrated exactly as the old code would have
  (steps whose marker is missing), then kept as differences with `schemaVersion: 1`. A profile the old code had
  already migrated (markers present) keeps its values. Values equal to today's defaults are no longer stored, so a
  later change of a default reaches them — the point of "store only diffs".
- **The edition.** The old code turned an emptied edition (`''`) back into the automatic one on *every* load — the
  same bug class; now only for profiles from before `schemaVersion`.
- **Settings files.** A file from before `schemaVersion` goes through all the steps whose marker it lacks (before:
  only the empty-title step); a file of this version is taken as it is. Exported files still hold the whole
  profile, now with `schemaVersion`.
- **Two tabs.** The `storage` event reaches only the *other* tabs. A tab follows text, images, profile, logo,
  language, theme, layout and the imported file's name. If both tabs type within the same 600 ms pause, the later
  save wins and the other tab takes it once idle (Known Issues ⚪). A tab of an older version writing to a newer
  profile changes only the one value (its own defaults cannot measure the newer differences).

## 4. Review

An independent review read the whole diff and the tests, ran `npm test` and `npm run lint`, and checked three
findings with a jsdom probe. Its verdict: nothing loses stored data for existing users in a single tab; `diff` /
`merge` handle `null`, `''`, numbers and arrays; Reset / Undo / import, the timers, `pagehide` and `images.reload`
are correct. Its findings, all applied:

| # | Finding | Applied |
|---|---|---|
| 1 | After a sync the second tab kept the previous file's export name (`Kelk.names` read `sourceName` at start only). | `K.names.followStored()` on `ui` and on a taken text; test. |
| 2 | A storage cleared elsewhere (`key` null) emptied the open text, and nothing saved it again. | Cleared storage: this tab writes its text and images back; test. |
| 3 | A tab of an older version calling `set()` dropped a newer profile's values (its diff measured against older defaults). | `set()` writes the one value into a newer profile's stored differences; test. |
| 4 | Language, theme and layout from another tab only reached the controls. | Applied on a `ui` change (`switchLang`, `K.ui.theme`, `K.ui.layout`); test for theme and layout. |
| 5 | Untested: the settings file and Undo of Reset through `settings.js`, cleared storage, the names sync. | Tests through the Settings pane (file input, Reset button, the toast's Undo) and the cases above. |
