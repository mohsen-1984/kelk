The generator-4 dimensions:

| Dimension | Values |
|---|---|
| `dir` | `ltr`, `rtl` — set by the document |
| `font` (right to left) | `vazirmatn`, `sahel`, `noto-naskh` |
| `latinFont` | the 8 Latin families; `-` on left-to-right files |
| `digits` | `ascii` 1 : `native` 1 : `asis` 1; `-` on left-to-right files |
| `tracking` | `none` 2 : `tight` (−0.04 em) 1 : `loose` (+0.08 em) 1 — CSS `letter-spacing` |

The `digits` values:

- **`asis`:** the document as written. fa-report and fa-mixed mix ASCII and Persian digits on purpose.
- **`ascii`:** every number in ASCII, with `.` `,` `%`.
- **`native`:** the running text's numbers in Persian (fa) or Arabic-Indic (ar) digits, written with ٫ ٬ ٪ as ar-article writes them. A number attached to a Latin word, directly or through one space or hyphen, stays ASCII: SHA-256, p95, Alpine 3.19, 64 GB, PostgreSQL 16.
- **Always kept as written:** code, link targets, addresses and list markers. Table cells count as text and are rewritten.

### Importer failures the RTL fuzz exposes (listed, not fixed — P3)

- **Right-to-left headings:** dev 67.6, held-out 74.0; fa-report dev 47.3.
- **Right-to-left quotes:** dev 66.7, held-out 51.5.
- **`tracking: loose`** (+0.08 em) costs about 15 points on left-to-right files: dev 80.7 against 96.2 untracked.
  Tables and code drop most. This is the real-producer form of the metamorphic `trackLoose` loss (−16).
- **Two columns** stay the weakest layout, now with right-to-left files in them.
- **`native` digits** are the weakest `digits` value (dev 73.1); `zwnj` is the weakest `rtl` part.
- **Persian digits read back as Arabic-Indic.** Some fonts draw a Persian digit and its Arabic-Indic twin with one
  shared glyph — Times New Roman and Tahoma do for ۱ and ١. Persian digits drawn with such a glyph come back as
  Arabic-Indic (`fz6-chr--fa-report`, dev, its `digits` part 0.111 in the first draw with `digits: native`; 0.766
  now that it draws `asis`, which has fewer Persian digits). The importer should choose Persian forms in a
  Persian document (`/Lang`, or the ک/ی letters around). This is for P3.

## 6. Open issues

- **wkhtmltopdf and `unicode-range` / `local()`** are not verified. If they are ignored, the wkhtmltopdf RTL files
  set Latin text in the RTL font, and Noto Naskh may not load in them. That affects only those files (about 11 per
  split); see §5 step 3.
- **The `-0.6` "change since last run"** in the local dev rerun compares the first and the fixed draw of generator 4
  (same env, different PDFs). Expected while `GENERATOR` stays 4 across the review fixes; it does not matter once the
  baseline is built.
- **`profile.js`'s tree-headings stat** ("fuzz-chr … mean") now includes right-to-left files, which score about 0
  there, as `chrome-rtl-tagged` already does (0.0). It fell from about 99.5 to 53.3. It is printed only, never
  failed. It also reads `corpus/<doc>.md` instead of a rewritten `<name>.md`. Split it by direction and read
  `source`, in P2.2 or P3.
- **`fonts-noto-core`** installs many Noto families, so the system fallback for glyphs no fuzz font has may change,
  for English files too. The baseline rebuild covers it.
- **`make-rtl.js`** selects every `corpus/(fa|ar)-*.md`. A full rerun would also print `fa-mixed` (it already picks
  up `fa-links`, `fa-math` and `fa-weights`). Give it an explicit list when it is next run.
- **Local figures are indicative only** (no wkhtmltopdf, Noto Naskh Arabic or Liberation / DejaVu / Inter fonts
  here). The CI run gives the official ones.
